## BIRD — fails hard criteria

- Comparator is `set(predicted_res) == set(ground_truth_res)` over `cursor.fetchall()`.
- Evaluation unit is an **unnamed tuple set**: no column names, no dtypes, no declared key,
  no documented per-column semantics. Frozen probes are defined over named-column
  tabular outputs; applying them requires reinterpreting their preconditions.
- **No databases and no gold SQL ship in the repo** (0 `.sqlite` files found). Reference
  outputs must be generated by executing gold SQL against a separately distributed
  database bundle.
- Both distribution hosts tested are unreachable from this environment (HTTP 000).

**Criterion 3 (reference outputs obtainable reproducibly): FAIL.** BIRD is excluded.

## Spider 2.0-lite — passes all ten hard criteria

1. Evaluator public and pinnable — yes, commit + file hashes above.
2. Clear comparison function — yes, `compare_pandas_table`.
3. Reference outputs reproducible — **yes, 1,544 gold execution-result CSVs ship in-repo**.
4. Valid paired outputs locally — yes, perturb the gold CSV; compare (perturbed, gold).
5. Some probes applicable without reinterpretation — yes, 5 of 7 (below).
6. Matched controls under the same rules — yes, unchanged.
7. No human annotation — yes.
8. No LLM judge — yes.
9. No proprietary service — **yes for comparator-level probing**; BigQuery/Snowflake are
   needed only to execute candidate SQL, which this design does not require.
10. Lightweight and local — yes, pandas + math.

Comparison semantics recovered from the pinned source: per-column vectors; each gold
column must match *some* pred column; `len(v1)!=len(v2)` returns False so row-count
changes are visible; absolute tolerance `1e-2`; all 547 instances declare
`ignore_order: true`; 293 declare `condition_cols`, restricting comparison to a subset
of gold columns.

**Two divergent comparators ship in the same repo.** The driver's copy adds
`normalize(value): if pd.isna(value): return 0` — an unconditional NaN-to-zero mapping
absent from the utils copy. This mirrors the null/zero equivalence found in the audited
ELT-Bench implementation, in an independently developed evaluator. It was observed while
locating the comparator and determining input format, which the anti-circularity rule
permits; no probe was created in response to it.

Operational note: 5 of 21 admissible probes raised `ValueError`/`IndexError` inside the
comparator (instances `bq003`, `bq022`). Recorded as operational status, never as a
semantic verdict.

## Task 6 answers

1. **Did the methodology transfer without redesign?** Yes, mechanically. Frozen probes and
   controls ran against an independent pinned evaluator with no new operators and no
   altered semantics.
2. **Were enough probes applicable to be meaningful?** **No.** Two of seven produced data;
   two are NOT_APPLICABLE by definition; three found no eligible instances.
3. **Interpretable paired outcomes?** Partially — 16 clean pairs, 5 evaluator exceptions.
4. **Evidence of a second-benchmark discrimination issue?** **No.** Δ = 0, zero discordant
   pairs. On these two probes Spider 2.0-lite's comparator rejects semantic and arbitrary
   edits alike.
5. **Would adding this materially improve the paper?** No, and it carries downside. A
   Δ = 0 result from 16 pairs on 2 probes is underpowered, and a reviewer may read
   "no selectivity on the second benchmark" as failure to replicate — converting a
   currently modest, defensible claim into a contested one.
6. **Fit in 4 pages?** No slack. It would need roughly 8–10 sentences plus a table,
   displacing existing methodological safeguards.

## Effort estimate for a full run

Roughly 1–2 days: sweep all 547 instances for probe eligibility (hours), then handle the
comparator exception classes, the `condition_cols` subsetting semantics, and the multi-gold
(`_a`/`_b`/`_c`) variants properly. The eligibility sweep is the cheap part; interpreting
`condition_cols` faithfully is the part that would need care.

## Decision

**SUBMIT CURRENT PAPER UNCHANGED.**

The transfer is mechanically clean but evidentially thin, and the one striking observation
(NaN→0 in the driver) cannot be measured by the frozen probes for lack of eligible data.
Measuring it would require designing a probe around evaluator internals — the exact
circularity the frozen catalogue exists to prevent. It is the seed of a follow-up study,
not a paragraph in this one.
